Fase 4D — Serialización binaria de Wisp v2

Construimos los bytes reales de tres paquetes Wisp de laboratorio: CONNECT, DATA y CLOSE. Como el endpoint de Postman cerró la conexión cuando enviamos mensajes WebSocket binarios, ahora envolvemos esos mismos bytes en Base64 para transportarlos como texto y reconstruirlos exactamente al regresar.

← Volver a Fase 4C Laboratorio principal
Base64 es solamente el envoltorio de transporte de esta prueba. Los bytes internos siguen usando la estructura de Wisp. Esto NO demuestra un socket Wisp real y el servidor de eco NO abre una conexión a example.com.

Formato que estamos serializando

byte 0 → packet type (uint8) bytes 1..4 → stream ID (uint32 little-endian) bytes 5..N → payload específico del paquete
