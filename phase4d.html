Fase 4D — Frames binarios inspirados en Wisp v2

En las fases anteriores inventamos nuestro propio protocolo de texto. Ahora construimos frames usando el formato binario real documentado por Wisp v2 y los enviamos a Postman Echo. El servidor de eco NO interpreta Wisp: solamente devuelve los mismos bytes para que nosotros los podamos decodificar localmente.

← Volver a Fase 4C Laboratorio principal
Esta prueba no abre conexiones hacia example.com. El hostname aparece únicamente como bytes dentro de un frame educativo. El único servidor de red contactado es ws.postman-echo.com.

Encabezado común de Wisp

byte 0 → packet type (uint8) bytes 1..4 → stream ID (uint32 little-endian) bytes 5..N → payload
Tipo Wisp Valor Equivalente de nuestro laboratorio
CONNECT0x01OPEN
DATA0x02DATA
CONTINUE0x03No lo modelamos todavía
CLOSE0x04CLOSE
INFO0x05No lo modelamos todavía

Frames que construiremos

Usaremos un único streamId = 7. El destino incluido en CONNECT será example.com:443, pero Postman Echo solo verá bytes y los devolverá sin abrir esa conexión.
