Fase 4E — Handshake Wisp v2 con máquinas de estado

Esta fase modela el handshake inicial de Wisp v2 usando frames binarios reales, pero sin conectarse a un servidor Wisp. Postman Echo solo transporta un sobre de texto con los bytes codificados en Base64. El cliente y el servidor Wisp son dos máquinas de estado locales dentro de esta página.

← Volver a Fase 4D Laboratorio principal
El servidor simulado NO abre sockets TCP/UDP ni contacta el hostname incluido en CONNECT. El único endpoint de red usado por esta fase es wss://ws.postman-echo.com/raw.

Secuencia que vamos a probar

1. C → S CONNECT stream=7 antes del handshake → REJECT 2. S → C INFO stream=7 → REJECT 3. S → C INFO stream=0, versión 2.1 → ACCEPT 4. C → S INFO stream=0, versión 2.1 → ACCEPT 5. S → C CONTINUE stream=0, buffer=8 → ACCEPT / READY 6. C → S CONNECT stream=7, TCP example.com:443 → ACCEPT
