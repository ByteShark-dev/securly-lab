Fase 5D — Wisp dentro del Transport Adapter

Esta fase une el routing de 5C con el wire format de Wisp que estudiamos en 4D. El Service Worker recupera una URL lógica fija y se la entrega a esta página. El adapter crea tres frames Wisp v2: CONNECT, DATA y CLOSE; Postman Echo solo transporta sus bytes codificados como Base64 y después el adapter los decodifica.

← Volver a Fase 5C Revisar Fase 4D Laboratorio principal
Esto NO es un servidor Wisp funcional ni un proxy. demo.invalid aparece únicamente dentro de los bytes del frame CONNECT. Postman Echo no interpreta Wisp y nadie abre una conexión TCP hacia ese hostname.
