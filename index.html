4. HTTPS al host de WebSocket

Abre el mismo hostname usando HTTPS normal. Aunque el servidor pueda responder con un error HTTP por esperar un upgrade, nos sirve para ver si Securly permite llegar al host.

5. WebSocket Echo

Chrome intentará abrir una conexión wss://. Si abre, enviará un identificador único y comprobará que el servidor lo devuelve. La prueba se cancela automáticamente después de 8 segundos.

Interpretación: si HTTPS y WSS fallan por categoría, el endpoint está siendo filtrado. Si HTTPS llega al host pero WSS falla, hay una diferencia de protocolo/handshake que merece estudiar. Si WSS abre y devuelve el mensaje, confirmamos que el navegador puede mantener una conexión WebSocket en este entorno.
