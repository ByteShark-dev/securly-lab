Fase 3B — Matriz de tipos de solicitud

Ahora probamos el dominio bloqueado usando tipos distintos de solicitud. El objetivo no es evitar el filtro, sino comprobar si la extensión trata igual una navegación principal, un subframe y un recurso de imagen.

Tipo Destino Resultado observado
main_frame https://neal.fun/ No probado
sub_frame / iframe https://neal.fun/ No probado
image https://neal.fun/favicon.ico No probado

1. Navegación principal

Abre neal.fun en una pestaña nueva. Esa pestaña cuenta como navegación principal del documento.

2. Subframe / iframe

La página intentará insertar neal.fun dentro de esta misma página. Así Chrome genera una solicitud de tipo subframe en vez de una navegación principal.

3. Recurso de imagen

Esta prueba intenta cargar el favicon de neal.fun como una imagen. No navega hacia la página completa.

Importante: que un iframe dispare su evento load no demuestra necesariamente que cargó el sitio original; podría haber cargado una página de bloqueo. Por eso la zona del iframe queda visible para inspeccionarla. Del mismo modo, un fallo de imagen solo nos dice que el recurso no pudo cargarse correctamente; después interpretaremos el resultado junto con la página de bloqueo de Securly.
