Fase 4F — Control de flujo con CONTINUE

Esta fase simula el control de flujo de un stream TCP Wisp ya abierto. El servidor anuncia cuántos paquetes DATA puede aceptar con CONTINUE y el cliente mantiene un contador local de créditos. Cuando llega a cero, el cliente debe dejar de transmitir DATA hasta recibir otro CONTINUE.

← Volver a Fase 4E Laboratorio principal
No se abre ningún socket TCP/UDP real. Los frames Wisp se construyen como bytes, se encapsulan en Base64 para que Postman Echo los transporte como texto y después se procesan mediante cliente/servidor simulados localmente.
