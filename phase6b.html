Fase 6B — Runtime virtual del navegador

Esta fase demuestra por qué cambiar únicamente src, href o el HTML inicial no basta. Una página también puede producir navegación y solicitudes desde APIs de JavaScript. Aquí usamos un runtime completamente local que intercepta operaciones ficticias y las traduce a rutas del laboratorio.

← Volver a Fase 6A Revisar Fase 5D Laboratorio principal
No se reemplaza ninguna API real del navegador. No se llama window.open(), fetch(), new WebSocket(), Worker ni importScripts(). Todo son objetos y strings de laboratorio.

Escenario lógico fijo

Documento lógico: https://demo.invalid/app/index.html Origen lógico: https://demo.invalid Origen real lab: ${location.origin}/securly-lab/ Objetivo: conservar la ilusión lógica de demo.invalid sin permitir que estas operaciones contacten demo.invalid.
